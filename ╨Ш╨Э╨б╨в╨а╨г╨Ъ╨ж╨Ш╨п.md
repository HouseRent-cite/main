# Инструкция по запуску сайта «Тихий берег»

Сайт состоит из двух частей:

- **GitHub Pages** — бесплатный хостинг, где лежат файлы сайта (внешний вид).
- **Supabase** — бесплатная база данных: тексты, цены, фото, вход в админку.

Вы один раз всё настраиваете (около часа), дальше заказчик сам меняет информацию через страницу `/admin/` — без GitHub и без кода.

> Всё описано для браузера на компьютере. Командная строка не нужна.
> Названия кнопок в GitHub и Supabase иногда немного меняются — если кнопка называется чуть иначе, ищите похожую по смыслу.

## 1. GitHub: регистрация и загрузка файлов

### 1.1. Регистрация
1. Откройте **https://github.com** → **Sign up**.
2. Введите email, придумайте пароль и имя пользователя (латиницей, например `tihiy-bereg`). Имя будет частью адреса сайта.
3. Подтвердите email кодом из письма. Тариф — **Free**.

### 1.2. Создание репозитория
1. Справа вверху **«+»** → **New repository**.
2. **Repository name**: например `site` (латиница, без пробелов).
3. Выберите **Public** (для бесплатного GitHub Pages репозиторий должен быть публичным — это нормально, секретов в коде нет).
4. Поставьте галочку **Add a README file**.
5. **Create repository**.

### 1.3. Загрузка файлов
1. Распакуйте архив с сайтом на компьютере.
2. В репозитории нажмите **Add file → Upload files**.
3. Откройте распакованную папку, **выделите всё её содержимое** (не саму папку, а то, что внутри: `index.html`, `object.html`, `admin`, `assets`, `supabase` и т. д.) и перетащите в окно браузера.
4. Дождитесь, пока все файлы загрузятся, внизу нажмите **Commit changes**.
5. Проверьте: в корне репозитория должны лежать `index.html`, `object.html`, папки `admin`, `assets`, `supabase`. Если всё оказалось внутри лишней папки — удалите и загрузите заново содержимое, а не саму папку.

### 1.4. Скрытая папка `.github` (автоматическая «побудка» базы)
Папки, начинающиеся с точки, часто не перетаскиваются (особенно на Mac). Проверьте, есть ли в репозитории папка `.github`. Если нет:
1. **Add file → Create new file**.
2. В поле имени файла напишите ровно: `.github/workflows/keep-alive.yml` (слэши сами превратятся в папки).
3. Откройте на компьютере файл `.github/workflows/keep-alive.yml` из архива любым текстовым редактором (Блокнот / TextEdit), скопируйте всё содержимое и вставьте.
4. **Commit changes**.

> Зачем это: бесплатная база Supabase «засыпает», если к ней 7 дней никто не обращается. Этот файл раз в 3 дня делает к ней один запрос. Подробнее — в разделе 9.

## 2. Supabase: база данных

### 2.1. Регистрация
1. Откройте **https://supabase.com** → **Start your project**.
2. Удобнее всего войти через **Continue with GitHub** (аккаунт из шага 1).

### 2.2. Создание проекта
1. **New project**.
2. **Name**: `tihiy-bereg` (любое).
3. **Database Password**: нажмите **Generate a password** и **сохраните пароль** в надёжное место (в повседневной работе он не понадобится).
4. **Region**: ближайший к посетителям (для России — `Central EU (Frankfurt)` или другой европейский).
5. Тариф **Free** → **Create new project**. Подождите 1–2 минуты.

### 2.3. Создание таблиц и хранилища фото
1. В левом меню **SQL Editor** (значок `>_`).
2. **New query** (или «+»).
3. Откройте из архива файл `supabase/01_setup.sql` текстовым редактором, **скопируйте весь текст** и вставьте в окно SQL Editor.
4. Нажмите **Run** (или Ctrl+Enter). Внизу должно появиться **Success. No rows returned**.
5. Если Supabase спросит про «destructive operation» — нажмите **Run this query** (скрипт ничего не удаляет из ваших данных, он только удаляет и пересоздаёт правила доступа).

Проверка: в меню **Table Editor** должны появиться таблицы `admins`, `properties`, `reviews`, `site_settings`; в меню **Storage** — бакет `photos`.

### 2.4. Где взять адрес проекта и публичный ключ
1. Слева внизу **Project Settings** (шестерёнка).
2. **Адрес (Project URL)**: раздел **Data API** (или кнопка **Connect** вверху страницы проекта). Выглядит так: `https://abcdefghijk.supabase.co`.
3. **Публичный ключ**: раздел **API Keys**. Подойдёт любой из двух:
   - **Publishable key** — начинается с `sb_publishable_...`, или
   - на вкладке **Legacy API keys** ключ **anon public** — длинный, начинается с `eyJ...`.

> ⚠️ **Никогда** не копируйте ключ **secret** (`sb_secret_...`) или **service_role**. Их нельзя вставлять в сайт — они дают полный доступ к базе.

### 2.5. Вставка ключей в сайт
1. В GitHub откройте репозиторий → папка `assets` → `js` → файл `config.js`.
2. Нажмите значок карандаша (**Edit this file**).
3. Замените:
   ```js
   export const SUPABASE_URL = 'https://YOUR-PROJECT-ID.supabase.co';
   export const SUPABASE_ANON_KEY = 'YOUR-ANON-KEY';
   ```
   на свои значения, **сохраняя кавычки**, например:
   ```js
   export const SUPABASE_URL = 'https://abcdefghijk.supabase.co';
   export const SUPABASE_ANON_KEY = 'sb_publishable_AbC123...';
   ```
4. **Commit changes** → ещё раз **Commit changes**.

## 3. Аккаунт администратора и запрет регистрации

### 3.1. Создать пользователя для заказчика
1. Supabase → **Authentication** → **Users**.
2. **Add user** → **Create new user**.
3. Email заказчика и временный пароль (минимум 8 символов).
4. Обязательно отметьте **Auto Confirm User** → **Create user**.

### 3.2. Дать этому пользователю права администратора
Просто пользователь ещё ничего менять не может — его email нужно внести в список администраторов:
1. **SQL Editor → New query**.
2. Вставьте содержимое файла `supabase/02_add_admin.sql`.
3. Замените `owner@example.com` на email заказчика (тот же, что в шаге 3.1).
4. **Run**. Внизу должна появиться строка с этим email.

Хотите, чтобы вы тоже могли заходить? Создайте себе второго пользователя (3.1) и выполните 3.2 со своим email.

### 3.3. Отключить публичную регистрацию
1. **Authentication** → **Sign In / Providers** (в старых версиях — **Providers** или **Settings**).
2. Выключите **Allow new users to sign up** → **Save**.

Даже если кто-то каким-то образом зарегистрируется, изменять данные он не сможет: база пускает только email-адреса из таблицы `admins`.

### 3.4. Адрес сайта для писем (восстановление пароля)
Сделайте после шага 4, когда будет известна ссылка на сайт:
1. **Authentication** → **URL Configuration**.
2. **Site URL**: `https://ВАШ-ЛОГИН.github.io/ИМЯ-РЕПОЗИТОРИЯ/admin/`
3. В **Redirect URLs** нажмите **Add URL** и добавьте тот же адрес → **Save**.

## 4. Включение GitHub Pages

1. В репозитории → **Settings** (вкладка вверху) → в левом меню **Pages**.
2. **Source**: **Deploy from a branch**.
3. **Branch**: `main`, папка `/ (root)` → **Save**.
4. Подождите 1–3 минуты и обновите страницу. Вверху появится: **Your site is live at** `https://ВАШ-ЛОГИН.github.io/ИМЯ-РЕПОЗИТОРИЯ/`.

Это и есть публичная ссылка. Админка: та же ссылка + `admin/`, например
`https://tihiy-bereg.github.io/site/admin/`

> Если назвать репозиторий в точности `ВАШ-ЛОГИН.github.io`, сайт будет открываться по короткому адресу `https://ВАШ-ЛОГИН.github.io/`. Всё остальное работает так же.

## 5. Как заказчику пользоваться админкой

Это можно переслать заказчику:

> **Вход:** откройте `https://…/admin/` (ссылка «Вход для владельца» есть и в самом низу сайта). Введите email и пароль.
>
> **Объекты** — список домов и бани.
> - «Изменить» — название, описание, цена, вместимость, удобства, правила, фото. После правок нажмите зелёную кнопку **«Сохранить»** внизу экрана.
> - Фото: «Загрузить фото» (можно выбрать несколько сразу, прямо с телефона). Первое фото — обложка. Стрелки ← → меняют порядок, ✕ — удаляет. Фото сохраняются сразу, без кнопки «Сохранить».
> - «Скрыть / Показать» — временно убрать объект с сайта, не удаляя его.
> - «+ Добавить объект» — создаёт новый скрытый объект. Заполните его, загрузите фото и включите «Показывать на сайте».
> - Стрелки ↑ ↓ в списке — порядок объектов на сайте.
>
> **Отзывы** — каждый отзыв сохраняется своей кнопкой «Сохранить».
>
> **Главная и контакты** — телефон, WhatsApp, Telegram, адрес, точка на карте, тексты главной страницы, фото первого экрана, преимущества, шаги бронирования, время заезда/выезда.
> - Координаты для карты: откройте Яндекс Карты, нажмите на нужное место, скопируйте числа вида `56.838, 60.597` и вставьте целиком в поле «Широта».
> - Если поле WhatsApp или Telegram оставить пустым — соответствующая кнопка исчезнет с сайта.
>
> **Аккаунт** — смена пароля, выход, резервная копия.
>
> Изменения появляются на сайте сразу. Если не видно — обновите страницу сайта.

Фото автоматически уменьшаются до 1920 пикселей и сжимаются перед загрузкой, поэтому можно загружать снимки прямо с телефона. Бесплатного места в Supabase (1 ГБ) хватит примерно на 3–4 тысячи таких фото.

## 6. Смена пароля администратора

**Способ 1 — из админки (если пароль известен):** войти → вкладка **Аккаунт** → «Сменить пароль».

**Способ 2 — забыт пароль:** на странице входа впишите email → «Забыли пароль?» → придёт письмо со ссылкой → откроется форма нового пароля. (Нужно, чтобы был выполнен шаг 3.4.)
> Бесплатный почтовый сервис Supabase отправляет всего несколько писем в час. Если письмо не пришло — проверьте «Спам» и подождите час.

**Способ 3 — через Supabase (вы как разработчик):** **Authentication → Users** → нажмите на пользователя → **Send password recovery** (письмо) или удалите пользователя и создайте заново (шаг 3.1) с новым паролем. Шаг 3.2 повторять не нужно, если email тот же.

## 7. Превью ссылки в мессенджерах (SEO)

Telegram, WhatsApp и ВКонтакте не запускают код сайта, поэтому заголовок, описание и картинку превью они берут из файла `index.html`. Поменяйте их **один раз**, когда будут реальные данные:

1. GitHub → `index.html` → карандаш.
2. В самом верху замените тексты в строках:
   - `<title>…</title>` — заголовок;
   - `<meta name="description" content="…">` — описание для поисковиков;
   - `og:site_name`, `og:title`, `og:description` — для превью в мессенджерах;
   - `og:image` — ссылка на картинку превью. Удобно так: загрузите хорошее фото в админке, откройте сайт, нажмите на фото правой кнопкой → «Копировать адрес изображения» и вставьте этот адрес.
3. То же самое (кроме description) — в начале `object.html`.
4. **Commit changes**.

Telegram запоминает превью надолго. Чтобы обновить: напишите боту **@WebpageBot** ссылку на сайт.

Иконка сайта (favicon) — файл `assets/img/favicon.svg`; можно заменить своей SVG-картинкой с тем же именем.

## 8. Свой домен (по желанию)

1. Купите домен у любого регистратора (Reg.ru, Timeweb, Nic.ru и т. п.).
2. GitHub → **Settings → Pages → Custom domain** → впишите домен, например `tihiy-bereg.ru` → **Save**.
3. В личном кабинете регистратора, в разделе **DNS-записи**, добавьте:
   - четыре записи типа **A** для `@`:
     `185.199.108.153`, `185.199.109.153`, `185.199.110.153`, `185.199.111.153`
   - запись **CNAME** для `www` со значением `ВАШ-ЛОГИН.github.io`
4. Подождите от 15 минут до суток. Когда GitHub покажет зелёную галочку — включите **Enforce HTTPS**.
5. В Supabase обновите **Site URL** и **Redirect URLs** (шаг 3.4) на `https://tihiy-bereg.ru/admin/`.

## 9. Резервная копия и «засыпание» базы

**Засыпание.** Бесплатный проект Supabase ставится на паузу после 7 дней без обращений. Пока на сайт заходят посетители, база не уснёт; дополнительно файл `.github/workflows/keep-alive.yml` раз в 3 дня её «будит». Если всё же уснула — Supabase пришлёт письмо; зайдите в проект и нажмите **Restore project** (1–2 минуты).

GitHub отключает такие автоматические задачи, если в репозитории 60 дней не было изменений, и присылает письмо — достаточно зайти в **Actions** и нажать **Enable workflow**. Проверить работу можно там же: **Actions → Supabase keep-alive → Run workflow**.

**Что видят посетители, если база недоступна.** Сайт не будет пустым:
1. Если посетитель уже заходил — увидит последнюю сохранённую в его браузере версию.
2. Иначе — данные из файла `assets/js/fallback.js` (сейчас там демо-заглушки).

Поэтому **после заполнения реальных данных** обязательно сделайте резервную копию:
админка → **Аккаунт** → **Скачать резервную копию** → в GitHub откройте папку `assets/js` → **Add file → Upload files** → загрузите скачанный `fallback.js` (он заменит старый) → **Commit changes**. Повторяйте после крупных изменений цен или контактов.

## 10. Частые ошибки и решения

| Проблема | Что делать |
|---|---|
| **404 по ссылке на сайт** | Подождите 2–3 минуты после включения Pages. Проверьте, что `index.html` лежит в корне репозитория, а не во вложенной папке. Проверьте Settings → Pages: ветка `main`, папка `/ (root)`. Адрес должен заканчиваться на `/имя-репозитория/` (регистр букв важен). |
| **Изменения в GitHub не видны на сайте** | Публикация занимает 1–3 минуты (статус — во вкладке **Actions**, зелёная галочка = готово). Затем обновите страницу с очисткой кеша: Ctrl+F5 (Windows) / Cmd+Shift+R (Mac); на телефоне — откройте в режиме инкогнито. |
| **Изменения из админки не видны** | Обновите страницу сайта. Если на сайте по-прежнему демо-данные — значит, сайт не может достучаться до базы: проверьте `config.js` (адрес и ключ, кавычки на месте, нет пробелов) и не на паузе ли проект Supabase. |
| **В админке «Админка ещё не подключена»** | Не заполнен `assets/js/config.js` (шаг 2.5). |
| **«Неверный email или пароль»** | Проверьте раскладку и Caps Lock. Убедитесь, что пользователь есть в Authentication → Users. Сбросьте пароль (раздел 6). |
| **«Email не подтверждён»** | Authentication → Users → пользователь → **Confirm email** (или пересоздайте с галочкой Auto Confirm User). |
| **«…не является администратором»** / **«Нет прав на изменение»** | Email не добавлен в таблицу `admins`. Выполните `02_add_admin.sql` с **точно таким же** email. |
| **Фото не загружаются** | Проверьте, что `01_setup.sql` выполнен полностью (в Storage есть бакет `photos`). Формат — JPG/PNG/WebP; фото с iPhone в HEIC лучше выбирать через «Фото», а не «Файлы» — тогда телефон сам переведёт их в JPG. Проверьте свободное место в Supabase (Project Settings → Usage). |
| **Карта не показывается** | Проверьте, что в «Широта» и «Долгота» числа через точку, например `56.838`. Блокировщики рекламы иногда прячут карты — попробуйте другой браузер. |
| **Нет связи с сервером / сайт показывает заглушки в России** | У части российских провайдеров адреса Supabase периодически не открываются без VPN. Посетители в этом случае видят резервные данные (раздел 9), поэтому держите `fallback.js` актуальным. Для работы в админке может понадобиться VPN. |
| **Красный крестик в Actions «Supabase keep-alive»** | Скорее всего, проект на паузе — нажмите Restore в Supabase. |
| **Сломалась вёрстка после правки файла** | В GitHub откройте файл → **History** → выберите прошлую версию → «…» → **View file** → скопируйте содержимое обратно. |

## 11. Структура файлов

```
├── index.html              — главная страница
├── object.html             — страница объекта (object.html?id=…)
├── 404.html                — страница «не найдено»
├── robots.txt
├── .nojekyll               — служебный файл для GitHub Pages
├── admin/
│   └── index.html          — админка (/admin/)
├── assets/
│   ├── css/
│   │   ├── style.css       — оформление сайта (цвета — в самом начале файла)
│   │   └── admin.css       — оформление админки
│   ├── img/
│   │   └── favicon.svg     — иконка сайта
│   └── js/
│       ├── config.js       — ⚙️ адрес и публичный ключ Supabase
│       ├── fallback.js     — резервные данные (если база недоступна)
│       ├── api.js          — загрузка данных
│       ├── ui.js           — общие элементы: шапка, подвал, просмотр фото
│       ├── icons.js        — набор иконок
│       ├── home.js         — главная страница
│       ├── object.js       — страница объекта
```
